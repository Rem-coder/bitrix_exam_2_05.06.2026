# CodexDev

Собственные доработки для Bitrix Framework (в этом проекте — «1С-Битрикс:
Управление сайтом», не облачный REST Bitrix24). ID модуля: `codexdev`.

## Установка

1. Разместить каталог модуля в `/local/modules/codexdev` (он уже там).
2. В административной панели открыть **Настройки → Настройки продукта → Модули**
   (`/bitrix/admin/partner_modules.php?lang=ru`) и установить **CodexDev**.
   Нужны права администратора, активный сайт и установленный модуль `iblock`.
3. Открыть `/local/codexdev/index.php` на этом же сайте.

Установщик создаёт тип `codexdev` и инфоблок **Метадата** с кодом
`codexdev_metadata` и XML_ID `codexdev.metadata`, привязывает новый блок ко всем
активным сайтам. Группе «Все пользователи» разрешено чтение, администраторам —
полный доступ. Для конфиденциальных данных измените права инфоблока.

Добавляются три элемента: «Название проекта», «Описание проекта», «Версия проекта».
Их XML_ID стабильны: `codexdev.metadata.title`, `.description`, `.version`.
Повторная установка ищет тот же блок по точным типу и XML_ID и добавляет только
отсутствующие тестовые элементы. Изменённые существующие записи не перезаписывает.
При неоднозначном совпадении блоков установка останавливается.

Страница использует компонент `codexdev:metadata.list`, выводящий максимум 10
активных доступных элементов: SORT по возрастанию, затем ID по возрастанию.
Учитываются сроки активности, права пользователя и привязка к текущему сайту.
Названия и текст экранируются; HTML из данных не исполняется.

## Удаление

Удалите модуль в том же разделе административной панели.
**Будут удалены все элементы этого инфоблока, включая добавленные вручную.**
Сам инфоблок, его настройки и тип сохраняются. При повторной установке
используется сохранённый блок и создаются три тестовых элемента.

Удаляются только развёрнутые файлы модуля:

- `/local/codexdev/index.php`;
- `/local/components/codexdev/metadata.list/.description.php`;
- `/local/components/codexdev/metadata.list/component.php`;
- `/local/components/codexdev/metadata.list/templates/.default/template.php`.

Опустевшие каталоги этих доработок удаляются. Посторонние файлы сохраняются.
При установке отличающийся существующий целевой файл не перезаписывается.
Исходный пакет `/local/modules/codexdev` сохраняется: это необходимо для штатной
повторной установки. Чтобы удалить сам пакет, после деинсталляции удалите этот
каталог вручную. Ядро и файлы в `/bitrix` модуль не меняет.

## Разработка и проверка

Бизнес-логика находится в `lib/metadata.php`; автозагрузка — в `include.php`.
Шаблон компонента и страница хранятся внутри `install/` и копируются при установке.
После изменения файлов поставки переустановите модуль (это очистит данные!)
либо обновите только соответствующие развёрнутые файлы вручную.

`php local/modules/codexdev/tests/lifecycle.php` — автономные проверки с подменой
Bitrix API: первая/повторная установка, очистка и восстановление тестовых данных,
копирование/удаление файлов, конфликт целевых файлов, права администратора и CSRF.
Они не заменяют проверку на настоящем Bitrix с базой данных.

На стенде с БД проверьте: установка → три записи и страница → повторная установка
без дублей → добавление своей записи → удаление (блок остался, элементов нет,
страница/компонент удалены) → установка (тот же ID блока, три записи).
Дополнительно проверьте отказ в чтении после снятия прав с группы пользователей.

## Источники API

- Модули: https://dev.1c-bitrix.ru/api_help/main/general/modules/index.php
- CIBlock::Add: https://dev.1c-bitrix.ru/api_help/iblock/classes/ciblock/add.php
- CIBlockElement::GetList: https://dev.1c-bitrix.ru/api_help/iblock/classes/ciblockelement/getlist.php

Официальный сайт при разработке возвращал HTTP 403. Сигнатуры и фильтры сверены
с исходниками ядра 24.0.796 в этом репозитории (`CModule`, `ModuleManager`,
`CIBlockType`, `CIBlock`, `CIBlockElement`). Полноценная интеграционная проверка
требует отсутствующей базы сайта.
